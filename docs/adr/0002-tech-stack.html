1背景

構想段階のサンプルは、外部ライブラリを使わない単体HTMLで作りました。PoC 以降は、複数人の同時利用、外部システムとの連携、サーバー側の権限判定が必要になります。ポートフォリオの他製品と運用をそろえるため、V3.5 の選定に従います。

2決定（案）

区分採用補足
OSUbuntu 26.04 LTSサーバー・コンテナの基盤
DBPostgreSQL 18自分の schema だけを migrations/ で管理する
バックエンドPython 3.13、FastAPIパッケージ管理は uv。uv.lock を必ずコミットする
フロントエンドReact、TypeScript、ViteNode 24 LTS。lockfile を必ずコミットする
実行環境Docker Composelocal・poc・stg で同じ構成を使う
インフラ定義OpenTofudeploy/onprem/・deploy/cloud/
認証Entra ID ＋ Cloudflare Accessポートフォリオ共通
CIGitHub Actionsmain への直接 push 禁止。PR → CI → Human Review（通常2名、重要3名）
リリースコンテナイメージSBOM・署名・Attestation を付け、digest で固定する。latest タグは使わない

3PoCで選定するもの

対象候補判断の基準検証項目
3D表示ライブラリ（未定：IFC と 3D Tiles を表示できるライブラリを2〜3種比較）読み込み10秒以内、30fps以上、ライセンス、ArcSphere との共通化T3
リアルタイム配信WebSocket、Server-Sent Events3秒以内の反映、同時20人、Cloudflare 経由での安定性T4
シミュレーションの実装方式Python（api 内）、ブラウザ内計算との併用16通りの試算を3秒以内、サーバーとブラウザで結果が一致することT5

4構想段階のサンプルの扱い

  • prototypes/offline-demo/ と prototypes/system-webui/ は、説明用・画面検討用として残します。本番のコードには取り込みません。
  • シミュレーションの考え方（タスク係数・重機稼働・EVM）は、PoC で Python に作り直す際の仕様の手がかりにします。

5結果と影響

  • ポートフォリオの他製品と同じ運用手順（CI、リリース統制、監視）を使えます。
  • 単体HTMLのサンプルとは別のコードになるため、画面の見た目と操作は 画面設計書を正として合わせます。
