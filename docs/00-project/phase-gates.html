1目的

PoC から運用・改善までの各フェーズで「何を確かめるか」「どうなったら次へ進むか」「どの文書をそろえるか」を定めます。ゲートで基準を満たさないときは、先へ進まずに止めるか、やり直すか、方向を変えます。

ポートフォリオ全体の段階（全体構成 V3.6 の第1〜第3段階）は事業全体の順序を示すもので、本書のフェーズは SiteLive Twin という1製品の進め方を示します。

3判定の種類

判定意味その後の扱い
Go判定基準をすべて満たした次のフェーズへ進む
条件付きGo必須の基準は満たしたが、軽微な未達がある条件と期限を判定書に書き、次のフェーズの中で解消する。期限までに解消しなければ再判定
やり直し必須の基準に未達があるが、見込みはある期間を区切って同じフェーズを延長し（原則4週以内）、再判定する
ピボット前提（対象業務・データ・利用者）が違っていた構想に戻り、範囲や対象を変えて G0 からやり直す
No-Go成立しない、または価値に見合わない中止する。わかったことを記録し、ポートフォリオの他製品に引き継ぐ

Prototype を実施するかの判断

G1 の時点で次のいずれかに当てはまれば実施し、当てはまらなければ G1 から MVP へ進みます。

  • PoC で画面の構成や操作の流れを大きく変えた
  • 現場の利用者（所長・工務）がまだ画面に触れていない
  • MVP の現場で、新しい入力作業（日報など）を求める

7ゲート判定の進め方

  1. プロダクトオーナーが判定書の案を作り、判定会議の3営業日前までに配る
  2. 判定会議で、基準ごとに証跡（測定結果・テスト結果・診断結果）を確認する
  3. 判定（Go／条件付きGo／やり直し／ピボット／No-Go）と、条件・期限を判定書に書く
  4. 判定者が承認欄に記入し、判定書をリポジトリに保存する（CHANGELOG にも記録）
  5. リスク・課題管理台帳と、次のフェーズの計画を更新する
