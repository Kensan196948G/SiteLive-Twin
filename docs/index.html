1このプロジェクト

全現場の状況を一目で把握し、問題の原因を3Dで確かめ、対策の効果をその場で試算して、すぐ決めるための業務システムです。判断の流れ「見る → 気づく → 原因を探す → 対策を比べる → 決める」を1つの画面で回します。

まず読む文書は 企画構想案、プロジェクト憲章、フェーズゲート定義書 の3つです。

5文書の書き方

  • 新しい文書は docs/_template.html をコピーして作ります（単体で開けるHTML、外部ファイルなし）。
  • 文書番号は「SLT-DOC-番号」。フォルダの番号（10＝PoC、20＝Prototype …）に合わせて振ります。
  • 技術的な判断は docs/adr/ に「NNNN-英小文字の題名.html」で記録します。
  • 未定の項目は （未定：…） と書き、決めるゲートを添えます。
  • 文書を更新したら、版と日付を上げ、ゲートの判定に関わる変更は CHANGELOG にも書きます。
