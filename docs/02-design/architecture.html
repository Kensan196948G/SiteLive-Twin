1概要

SiteLive Twin は、他のシステムが持つ3Dモデル・工程・原価・設備データを参照し、現場の「いまの状態」を集約して配信するシステムです。自らが正本として持つデータは最小限に絞り、みらい建設土木DX・AI統合基盤（全体構成 V3.6）の連携ルールに従います。

関連文書：要件定義書（SLT-DOC-10）、データ設計・連携仕様書（SLT-DOC-22）、ADR-0001、ADR-0002

2ポートフォリオ上の位置付け

V3.6 の12リポジトリには、現在 SiteLive Twin は含まれていません。独立リポジトリとして PoC を進め、MVP 終了時（G3）に位置付けを再評価します（ADR-0001）。

範囲が重なる既存製品

  • Civil-4D-AI-Planner：作業単位の4D施工安全計画。SiteLive Twin は安全イベントの表示にとどめ、安全計画は持ちません。
  • Construction-Public-Twin-Portal：住民向けの公開ポータル。利用者が異なるため、データの共有は MCIP・ArcSphere を介して行います。

6権限とセキュリティ

  • 認証：Cloudflare Access が Entra ID で利用者を確認し、API は受け取った ID トークンを検証します。ロールは Entra ID のグループから割り当てます。
  • 認可：すべての API でサーバー側の権限判定を行います。権限は「閲覧」「対策の起案」「承認・差戻し」「日報の作成」「設定の変更・リセット」の5つです（画面設計書 6章）。
  • 職務分掌：承認 API は「起案者と承認者が同じ」場合に拒否します（R3 二者承認）。
  • 監査：操作はすべて追記のみの監査ログに残し、承認の証跡は MCIP に記録します。
  • 秘密情報：接続情報や鍵はリポジトリに置かず、環境ごとの秘密情報管理を使います。
  • AI：MCAH 経由でのみ使い、プロンプトと応答の記録は MCAH・MCIP の規定に従います。
  • サプライチェーン：リリース成果物に SBOM・署名・Attestation を付け、コンテナは digest で固定します。
