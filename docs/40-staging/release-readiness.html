1目的と使い方

Staging フェーズの問い「本番に近い条件で、安全・安定して運用できるか？」に答え、本番環境で対象ユーザーへ正式提供してよいかを判断するための判定書です。G4（リリース判定）で使います。

  1. Staging 期間中に、3章の各項目を確認方法に沿って確かめ、証跡（報告書・ログ・画面の記録など）のある場所を記入します。
  2. 結果欄に「適合」「一部適合」「不適合」「対象外」のいずれかを記入します。
  3. 必須項目がすべて適合で、残っているリスク・課題が許容できれば Go、条件付きで許容できるなら条件付き Go とします。
  4. 6章の承認者が署名し、判定を確定します。

判定欄：必須＝不適合のままではリリースできない項目　推奨＝不適合でも条件付き Go で進められる項目

7例外の扱い

  • 必須項目を満たさないままリリースすることは原則として認めません。
  • 業務上どうしても必要な場合は、例外の内容・理由・影響・代わりの対策・期限を記録し、6章の承認者全員の合意に加えて、経営層の承認を得ます。
  • 例外はリスク・課題管理台帳に登録し、期限までに解消します。期限を過ぎた場合はプロダクトオーナーが経営層へ報告します。
  • セキュリティ（S-01〜S-08）の不適合は例外の対象にしません。
