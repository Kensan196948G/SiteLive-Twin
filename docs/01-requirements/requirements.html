1背景と目的

建設現場の工程・現場の状況・原価は、Excel、写真・チャット、基幹システムに分かれています。遅れが経営層に届くのは週報や月次会議のときで、原因の確認や対策の比較にも時間がかかります。

SiteLive Twin は、現場の状態を3Dモデルの上にほぼリアルタイムで重ね、計画とのずれを自動で検知し、対策の効果を試算して承認まで進められる業務システムです。経営判断の流れ「見る → 気づく → 原因を探す → 対策を比べる → 決める」を、1つのシステムの中で途切れずに回すことを目的とします。

6制約

みらい建設土木DX・AI統合基盤（全体構成 V3.6、リポジトリ構成ベストプラクティス V3.6、OS・アプリ選定 V3.5）に従います。

  • 正本の範囲：SiteLive Twin が正本として持つのは「現場ライブ状態の集約ビュー・イベント」と「対策シミュレーション案（申請）」だけです。3Dモデル（ArcSphere）、工程・原価・契約（CEOS）、案件ID・承認・証跡（MCIP）、気象（CODIP）、確定版文書（CDE）は参照のみとします。
  • 連携方式：他リポジトリのDBへは直接接続しません。版付きの契約（contracts）、API、MCAH 経由のイベントで連携します。
  • IoT時系列：正本は各設備システムまたは時系列保管領域です。SiteLive Twin は集約値を PostgreSQL に持ちます。
  • AI：MCAH の Tool Gateway・Model Gateway 経由でのみ使います。AI 提供元を直接呼び出しません。日報の下書きは R1、対策の承認は R3（二者承認）とします。
  • 認証：Entra ID → Cloudflare Access を使います。
  • 開発統制：main への直接 push は禁止です。Branch → PR → CI → Human Review（通常2名、重要な変更は3名）→ Merge の順に進めます。
  • 技術スタック：Ubuntu 26.04 LTS、PostgreSQL 18、Python 3.13＋uv、FastAPI、React＋TypeScript＋Vite、Node 24 LTS、Docker Compose、OpenTofu（ADR-0002）。

7対象外

対象外とするもの理由・担当
3Dモデル・点群・図面の作成と編集ArcSphere・Web-CAD の範囲。SiteLive Twin は参照して表示する
工程計画の作成、原価・契約の管理CEOS の範囲。SiteLive Twin は実績と予測を重ねて表示する
作業単位の4D施工安全計画Civil-4D-AI-Planner の範囲。安全イベントの表示は行う
住民・発注者向けの公開Construction-Public-Twin-Portal の範囲
重機の遠隔操作・自動運転安全上、本システムでは扱わない
勤怠・給与の計算人事システムの範囲。入退場は人数の集計にだけ使う
